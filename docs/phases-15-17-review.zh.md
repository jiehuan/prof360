## 3. Phase 15：D&O 风险核心层（已完成）

**目标。** 在扩大范围之前，先覆盖证券集体诉讼的主要驱动因素：股价大跌、业绩不及预期、内部人卖出、披露和会计问题、诉讼与监管调查。在 9 家试点公司上完成并验证。应用库结构不变（方案 A）：新指标进 `MatrixData`，新事件经信号和洞察进 `StrategicRisk`。

### 3.1 做了什么

| 项目 | 内容 | 关键规则或结果 |
|---|---|---|
| 15a 市场 | 日线复权价（保留 7 年）、实际与预期 EPS、以 SPY 为基准 | 指标：市值、90 天波动率、52 周最大回撤、EPS 超预期幅度。市值 = 季末收盘价 × 封面股数（期末后 120 天内），没有时用稀释加权股数 |

### 3.3 验收证据

- Ford 2024-07-25：下跌 18.4%，当天 SPY 下跌 0.5%；此前 EPS 0.47，预期 0.68：`stock_drop` 和 `earnings_miss_drop` 都被识别。
- Form 4：EDGAR 列出的每一份都已登记（9 家，0 缺失）。没有标为计划内的卖出，其文件里都没有出现 10b5-1。
- 诉讼留出测试（PFE、JPM、LUMN，没有参与写 prompt）：41 条事项，类型全部正确；引文按设计必然能在原文找到。
- 治理：8 份委托书中 7 份找到审计费（JPM 是文字叙述，两次读取不一致）；CEO 任职年份 8 份中 5 份。

### 3.4 未完成

- 同一公司内的 LLM 调用仍是串行，并且在阶段的数据库事务之内。
- SecureGPT 的每分钟请求数配额未知；gpt-6-luna 价格是暂定的。
- 9 家冷启动 10 分钟以内的目标没有实测（需要服务器数据库和一次付费运行）。

## 4. Phase 16：S&P 100（第一次全量运行完成）

**目标。** 每家公司都有通用核心层（XBRL 核心加 Phase 15 的风险层）和一个行业模块，不做逐家定制。

### 4.1 公司

- 2026-09-21 的 S&P 100（100 家；GOOGL 和 GOOG 是同一个 CIK）加上不在其中的 7 家试点公司：共 **107 家**。CIK 取自 SEC 的 ticker 列表，并逐家对照申报记录核实。
- **22 家（21%）需要人工指定行业**，因为 SIC 代码会误导：例如 3M（SIC 3841，医疗器械）是工业公司；Visa 和 Mastercard（7389，商业服务）是支付；CVS（5912，药店）是管理式医疗；Amazon 和 Booking 是互联网。每家在配置里写明原因。
- **前身申报主体。** ExxonMobil（2026 年）和 BlackRock（2024 年）改用新控股公司的 CIK，历史数据、最新 10-K 和委托书还在旧 CIK 下。新增设置 `predecessor_ciks`：facts、documents 和 signals 阶段两边都读。

### 4.3 工程改动（不大；主要工作是配置）

Phase 16 到目前为止：不含测试 fixture，+2,351 / −217 行，其中配置 +1,378 行，代码 +413 / −117 行。

- **从 10-Q 学习财年。** Costco 和 PepsiCo 的财年是 12/12/12/16 周，季度结束日最多比月末早三周。现在季度结束日取自公司自己的 10-Q；Alpha Vantage 把这类季度记在月末，所以业绩匹配允许 25 天误差。
- **新单位 `count`**（会员数、车辆数、桶 / 天），以及新的抽取 prompt 版本 `text_metrics_v3`。
- **补充 tag。** 银行和券商的净收入、公用事业的营业收入、利息费用的替代 tag、分开标注的折旧和摊销、几种债务组合、没有营业利润行时的 EBITDA（税前利润 + 利息 + 折旧摊销）。
- **覆盖率说明按行业组写**（`"*"` 表示所有公司），整个行业共有的缺口不再逐家写。
- **Claude 调用时限**：每次调用（含重试）最长 10 分钟（只用于开发）。第一次全量运行中几次长时间卡住，原因是笔记本电脑空闲睡眠（进程被冻结、计时也停止）；本地长时间运行改用 `caffeinate -i`。
- **重述的年度。** 第四季度 = 年度 − 前九个月。中间如果有文件重述了某个财年（107 家里有 19 家自 2022 年起有重述：分拆、终止经营、列报方式改变），这个季度就吸收了全部重述差额，例如 Bank of America 2025 年第四季度收入算出来是 31,180，按重述后口径约 28,400。现在这样的季度显示 N/M，由它算出的指标也是 N/M；年度用最新的重述值。否决的方案：保留错误值（DQ 看不出来），或用首次报告的年度值来推（存下的年度和季度对不上）。
- **BlackRock** 的总收入标注为合同收入；它的 `us-gaap:Revenues`（每年约 110–130 亿美元）不是总收入。用公司级覆盖（`company_overrides/BLK.yaml`）。
- **新闻稿与 XBRL 的核对。** 新闻稿写的是取整的标题数字（"净利润 18 亿美元"，XBRL 是 1,777M）时，只要 XBRL 按同样精度取整后等于它，就算一致。新闻稿的定义改为要求表格里的精确数字，并写明是哪一行（"Net income attributable to <公司>"，不是"available to common shareholders"、"profit"或调整后数字）。新的读取不再产生的核对记录会被删除。
- **insights 并行。** insights 和 metricdetail 在每次调用模型前提交已完成的写入，等待模型时不占数据库事务；在 SQLite 上也能同时处理 4 家（约每分钟 1 家，原来每家 3.5 分钟）。

### 4.4 覆盖率的做法和结果

循环约 8 次：对 107 家运行 facts 和 compute → 覆盖率报告（每个指标目标 5 个财年 + 8 个季度）→ 对每个缺口，查这家公司实际用的 tag → 在配置里加 tag 或公式（同样申报方式的公司一起修好），或者写说明（整个行业都缺的写在行业组下）→ 重跑。

| | 首次运行 | XBRL 循环之后 | LLM 全量之后 |
|---|---|---|---|
| 未说明的 XBRL 缺口 | 1,351 | **0** | **0** |
| 公司 × 指标行：OK / 有说明 / 部分缺失 / 没有数据 | — | 3,575 / 479 / 0 / 96 | 3,616 / 479 / 28 / 27 |

剩下的 55 个缺口都是文本指标或基于它们算的比率，例如 8 家银行里 6 家没有无保险存款，Walmart 没有可比销售增长。每个都要写说明或修复，这是覆盖率方面剩下的工作。

### 4.7 推迟的内容（记录在 D-052）

- 只在附注或 Item 2 里的内容，文本抽取不读：客户集中度、油气储量。
- S&P 100 里只有一两家、各家定义不同的模块：REIT 的 FFO 和出租率、ARPU、公用事业灾害成本、汽车召回、保险综合成本率。
- 多类股公司（Alphabet、Visa、Berkshire）的市值偏低：需要按股票类别的股数。
- Wells Fargo 和 American Express 的贷款总额没有用标准 tag 标注（需要公司自定义概念）。缺口已有说明。

## 5. Phase 17：约 98% 的上市运营公司（计划，未确认）

### 5.1 范围（"口径 A"）

### 5.2 现在的覆盖率和目标

| | 家数 | 占比 |
|---|---|---|
| Phase 16 的行业组，按 SIC | 2,995 | 71.4% |
| + 7 个带模块的新组、+ 6 个映射补充 | 4,003 | 95.4% |
| + 7 个只改映射的新组 | **4,117** | **98.1%** |

带模块的新组（XBRL 优先，每组最多 3 个文本指标）：SPAC 空壳（174）、化工和材料（134）、采矿和金属（89）、医疗服务（73）、建筑和住宅开发（52）、休闲和博彩（38）、餐饮（37）。只改映射的新组（用通用指标，不加新指标）：商业服务、批发、仪器、耐用消费品和服装、房地产运营、农业、消费服务。另有 9 个已有组扩大 SIC 范围。

### 5.3 临床阶段特性

收入低于 1,000 万美元的生命科学公司（390 家，占范围的 9%）按 SIC 落在制药或医疗器械，但研发 / 收入对它们没有意义。公司配置里设一个特性（由名单脚本建议、人工确认、每季度复核），改用现金可支撑季度数（按近期消耗速度）和研发占运营支出比；可支撑少于 4 个季度时出信号。

### 5.4 前提和规模

- **必须先做 Phase 10：**分层处理（约 800 家全量、3,200 家轻量、洞察按需）和多个 worker 领取任务。现在是一个进程按顺序跑各阶段；同一阶段内的公司可以并行（服务器数据库上所有阶段，SQLite 上只有 insights 和 metricdetail）。
- 其余 LLM 阶段（文本指标、治理、诉讼、信号、评分、新闻）和 insights 一样改为短事务，公司内部互不依赖的调用同时进行。
- 约 4,000 个 CIK 的名单由脚本生成、人工审阅后提交，不在运行时生成；每季度出一份差异报告（新上市、退市、SIC 变化）。
- Alpha Vantage：每天约 8,000 次调用，需要付费版的分钟配额。
- 首次全量的费用按 Phase 16 实测的每家成本推算，再按预算确定 Tier 1 的范围。

### 5.5 剩下的约 2%（78 家）及以外

48 家没有 SIC（逐家人工指定行业），17 家 BDC 和控股投资公司（需要 BDC 模块），13 家航运公司（需要 TCE、船队利用率）。外国发行人另开阶段（IFRS、20-F 章节、没有 Form 4 和委托书）。

### 5.6 Phase 17 需要的决定

1. SPAC 是否在承保范围内？（不含 SPAC，覆盖率仍约 98%。）
2. 约 4,000 家的名单放在哪里，谁负责每季度审阅。
3. 临床阶段的收入门槛（1,000 万美元）。
4. Tier 1 的范围和首次全量的预算。
5. 新单位（盎司、吨、磅）只用于显示，还是也参与同比和阈值。

### 5.7 开发样本：每个行业收入最大的 5 家（已定）

开发阶段不跑约 4,000 家，先用样本：38 个行业组（Phase 16 的 24 个加 Phase 17 的 14 个）每组取收入最大的 5 家。按 EDGAR 数据实测：共 **187 家**（PAYMENTS 按现在的映射只有 Visa 和 Mastercard），其中 68 家已在现在的 107 家里，**新增 119 家**，合计 **226 家**。规模与 Phase 16 相当。

名单人工审阅，不直接用收入排序：
- 有几个组按收入排序不合适：SPAC 没有收入（改按信托规模）；券商组里 StoneX、Galaxy 的交易总收入排在 KKR、Blackstone 前面。
- SIC 分错组的要用 `industry` 改：Nike（SIC 3021 橡胶鞋，进了化工）、Cintas（服装 SIC，实为制服租赁）、Plains All American、Plains GP 和 HF Sinclair（SIC 4610 管道，进了运输，实为能源中游和炼油）、Coinbase（进了 CREDIT）。
- PayPal、Fiserv、FIS 按 SIC 不在支付组。

### 5.8 样本做完后冻结，直接对全部公司上线（已定）

226 家通过质量关口之后，不再按公司调整：
- 只在通用层面改：行业组的 SIC 映射、指标集、tag 候选、公式、行业组级覆盖率说明、DQ 规则；每次改动对整个行业生效。
- 样本外不加公司级设置：不加公司级覆盖（像 BlackRock 那样），不加公司级覆盖率说明；`industry` 只用于样本审阅时发现的分错组，以及上线后承保人员报告的问题。
- 样本外的覆盖率缺口和 DQ 发现只按行业组统计比例，不逐家说明；某个组的错误比例高，说明是通用规则的问题。
- 上线的前提：Phase 10（分层、多 worker）、其余 LLM 阶段改短事务、Azure 部署和 SecureGPT、Alpha Vantage 付费版。

### 5.9 行业组以外的公司：由 LLM 在已有指标集里选（已定，PLAN 17g）

用户输入的公司不属于任何行业组时（例如没有 SIC、BDC、航运）：
- 一次 LLM 调用（SecureGPT）读业务描述（10-K Item 1 节选、SIC 说明）和已有的行业组及指标集，选出最接近的行业组或几个已有的指标集，理由引用业务描述原文。
- 边界：只能选已有的指标集，不新造指标或公式；通用核心层总是包含；集合代码按 schema 校验；两个模型一致才用，否则用复核模型的结果并进复核队列。
- 选择结果存表、之后沿用（业务描述变了才重选），在应用里标注"指标由 AI 按业务描述选择"，写进已有的 `Methodology` 文本（应用库结构不变）。
- 外国发行人（20-F / 40-F）不在此列：它们需要 IFRS 映射。

## 6. 我们已经看到的风险和取舍

1. **开发环境里双重检查用的是同一个模型。** 文本指标两次读取一致才保存，但开发时两次都是 Haiku（不同的 effort），所以"一致"的证明力比生产环境弱（生产是 gpt-6-luna 对 gpt-6-sol）。在有生产运行之前，对照原文的留出测试更重要。
2. **SIC 对大公司太粗。** S&P 100 有 21% 需要人工指定行业。Phase 17 按 SIC 范围映射约 4,000 家，人工审阅少得多；分错组的公司会悄悄拿到错误的模块。
3. **覆盖率说明可能掩盖真正的缺口。** 行业组级和 `"*"` 说明（例如"商誉减值只在发生减值的年份标注"）效率高，但一条宽泛的说明会解释很多行。每条说明写的时候都对照过公司数据，但之后没有机制重新核对。冻结之后（§5.8）只有样本写说明，样本外的缺口只看比例。
4. **诉讼基线。** 公司第一次运行找到的事项是基线，不进复核。新加入的 98 家，现有事项全部是基线。近期且仍在进行的事项仍会出信号，但没有人把它们当作"新事项"复核。
5. **Phase 17 依赖一个 Phase 16 没有做的 REIT 模块。** 计划把"房地产运营"公司映射到"Phase 16 的 REIT 模块（出租率、NOI）"，而这个模块被推迟了。计划要么补上这个模块，要么改映射。
6. **吞吐量。** insights 和 metricdetail 已改为等待模型时不占数据库事务，在 SQLite 上也能同时处理 4 家，实测约每分钟 1 家（原来每家 3.5 分钟）。其他 LLM 阶段的调用仍在每家公司一个事务之内：在 SQLite 上一次一家，在 Azure SQL 上长时间占锁。改造计划放在 Phase 17（17d），Phase 17 还依赖尚未开始的 Phase 10。
7. **外部依赖。** 需要 Alpha Vantage 付费版（股价、预期、新闻）；SecureGPT 的 RPM 配额和 gpt-6-luna 的价格未知；Alpha Vantage 的业绩日期按 25 天误差匹配季度结束日，比精确匹配宽松。
8. **学到的财年依赖申报方的标注。** 季度结束日取自 10-Q 自己的财务期间标注；标错的 10-Q 会让季度错位。Golden 测试只覆盖了 Costco。
9. **重述后的 N/M 季度。** 重述过的年度，其第四季度（及由它算出的指标）在应用里显示 N/M，直到前九个月也被重述；较早的年度永远不会。这是正确的，但承保人员会看到一些季度是 N/M。
10. **冻结后不再按公司调整（§5.8）。** 样本外 SIC 分错组的公司会一直用不对口的模块；公司特有的标注方式（像 BlackRock）会让个别指标缺失或偏差；DQ 会报出来，但不逐家修。
11. **AI 选择的指标集（§5.9）** 是唯一一处指标清单不由人工维护的地方。边界（只用已有集合、两个模型、存表可复核）能控制住范围，但对业务特殊的公司仍可能选错。

| 术语 | 含义 |
|---|---|
| XBRL | SEC 申报文件里机器可读的标签；财务报表指标的来源 |
| 10-K / 10-Q / 8-K | 年报 / 季报 / 重大事项临时报告 |
| Form 4 | 高管、董事和 10% 以上股东的交易报告 |
| 13D | 持股超过 5% 且可能施加影响的投资者提交的文件 |
| 10b5-1 计划 | 预先安排的交易计划；此类卖出不计入内部人卖出信号 |
| MD&A | 管理层讨论与分析，大部分文本指标出自这里 |
| EX-99.1 | 附在 8-K 里的业绩新闻稿 |
| SIC | SEC 给每个申报主体的标准行业分类代码 |
| Golden 测试 | 把管线输出和从申报文件手工录入的数字对比的自动测试 |
| 覆盖率说明 | 某家公司或某个行业缺某个指标的书面原因 |
| 双重检查 | 同一段文字独立读两次，一致才保存 |
| Grounding（引文核对） | LLM 的回答只有引文和数字能在原文找到时才保留 |
